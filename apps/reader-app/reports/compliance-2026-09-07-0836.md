## Overall verdict

**Partially compliant.** `navigation-routing.yaml`'s two new `micro` rules are
implemented and verified: relative links in rendered markdown are now resolved by
pure `./`/`../` arithmetic against the current file's real path and routed
through the app's own router — **no page reload, and no more "Cannot GET"** on a
clicked link. `link-resolve.ts` is pure and unit-tested (27/27 tests); the
content-pane click handler and the `currentFileDir()` / `followLink()` pair
carry it into the app.

Two things still need the author, both unchanged in nature:

1. **`docs/README.md`'s links are written for the old flat layout**
   (`creators/design-document.md`) but the folders are now
   `docs/personas/1-creators/`. Per the spec's "pure arithmetic, no guessing"
   rule these resolve to a non-existent path → in-app not-found. Fix by updating
   `docs/README.md` to the real paths, or by relocating the README so its
   relative paths line up. **This is a content fix, not a code fix — the spec
   forbids the app from remapping `creators/` to `personas/1-creators/`.**
2. **A URL typed into the address bar with a `.md` extension**
   (`/creators/design-document.md`) still hard-404s before SPA fallback on the
   dev server / typical static hosts — the app's own URLs drop the extension for
   exactly this reason (the standing `url-mirrors-real-path` deviation).

Plus the pre-existing "README" naming conflicts across `content.browser` /
`view.state` / `system.yaml`, unchanged.
