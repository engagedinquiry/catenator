## Overall verdict

**Partially compliant.** `navigation-routing.yaml`'s refined rules — including
the new "no hardcoded folder-name list for link resolution" `mustNever` — are
satisfied by the existing implementation with **no code change**:
`link-resolve.ts` `resolveRelativePath` is pure `./`/`../` segment arithmetic
with no lookup table, and the spec's exact new example (a `docs/README.md` link
written as `personas/1-creators/1-catenator-for-creators.md`) was verified
in-browser to resolve to `/personas/1-creators/1-catenator-for-creators`, render,
and set the dropdown — no page reload, no "Cannot GET". 27/27 tests.

Unchanged and still needing the author:

1. **The pre-existing "README" naming conflicts** — `content.browser`
   `macro.behavior`, `view.state` `macro.intent` + a `mustNever`, and
   `system.yaml` still say "README" for the persona default while
   `content.browser.first-file-is-folder-default-content` (built) says
   "first-sorted file". `navigation-routing.yaml` route text was fixed this run;
   the others still lag.
2. **A URL typed into the address bar with a `.md` extension** still hard-404s
   before SPA fallback on the dev server / typical static hosts — the app's own
   URLs drop the extension for exactly this reason (standing
   `url-mirrors-real-path` deviation).
3. **`delivery` return shape** is `{type,text,name}` not `{ markdownContent, title }`.
